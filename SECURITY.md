# Security Policy and Authorized Use

This repository accompanies research on hardening web application firewalls against SQL-injection
and cross-site-scripting attacks. Read this file before using anything here.

## 1. Dual-use nature of this work

GenWebSec studies WAF evasion in order to build better defenses. Work of this kind is inherently
dual-use: the same understanding that lets a defender write a rule that generalizes beyond one
observed payload could help an attacker craft a payload that evades one.

We have made deliberate choices to keep the useful half and withhold the operational half:

- **Attack-agent prompts are not published.** They are the component that most directly transfers to
  offensive use, and they are withheld permanently. This is a safeguard, not an omission.
- **Raw generated bypass payloads are not published.** The repository releases counts, rates,
  identifiers, and aggregate statistics instead.
- **Defensive material is published.** Generated ModSecurity rules, admission outcomes, benign
  corpora, and the defense-agent prompts, with worked examples redacted, are released so that the
  defensive claims can be checked and reused.

If you believe some released artifact still carries meaningful offensive capability, please tell us
using the contact below rather than opening a public issue.

## 2. Authorized use only

Everything in this repository is provided for defensive security research, reproduction of the
published results, and education.

**You may use this material only against systems you own or are explicitly authorized in writing to
test.**

Do not use it to probe, scan, exploit, or evade the protections of any system without that
authorization. Unauthorized testing of computer systems is illegal in most jurisdictions,
irrespective of intent, and the presence of this research material is not permission of any kind.

The controlled applications used in this study, and the third-party targets bWAPP and OWASP Juice
Shop, are intentionally vulnerable software meant to be run in an isolated local environment. Do not
deploy them on a public network.

## 3. Handling generated attack payloads

Although the raw bypass payloads are not published here, anyone who reruns the pipeline will produce
them locally. Treat them as security-sensitive artifacts:

- Keep them on the isolated research host where they were generated.
- Do not commit them to public repositories, paste them into public issues, or attach them to public
  discussion.
- Do not publish payloads that are still effective against a currently deployed production WAF
  configuration.
- If you need to share them for peer review, use a controlled-access channel and say plainly what the
  material is.

The same applies to run logs, which may contain payload text. Sanitize before sharing.

## 4. Responsible disclosure

If you find that this artifact discloses something it should not, we want to hear about it. This
includes:

- attack-agent prompt text, fragments, or template variables surviving anywhere in the repository,
  including inside logs, results files, or rule comments;
- credentials, API keys, access tokens, or private infrastructure identifiers;
- generated attack payloads that we intended to withhold;
- a published rule or corpus that leaks sensitive information about a third-party system; or
- a bypass technique visible in this artifact that defeats a current, widely deployed WAF
  configuration.

Please report these privately first.

**What we ask:** give us a reasonable period to respond and remediate before publishing, and do not
access, modify, or exfiltrate data belonging to anyone else while investigating.

**What you can expect:** an acknowledgement of your report, an assessment, and credit in the
repository changelog if you would like it.

Findings about ModSecurity, the OWASP Core Rule Set, bWAPP, or OWASP Juice Shop themselves should go
to those projects through their own disclosure processes. We are happy to help route a report if you
are unsure where it belongs.

## 5. Scope

This policy covers the contents of this artifact repository. It does not cover the upstream projects
named above, and it is not an offer of a bug bounty.
