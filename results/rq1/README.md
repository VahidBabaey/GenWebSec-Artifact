# RQ1: attack discovery against the baseline WAF

**Question.** Can the LLM attack agent find execution-valid SQLi and XSS attacks
that bypass the CRS-only baseline?

This directory holds the complete run-level RQ1 outputs, **payload-free**. The raw
per-candidate records contain the attack payloads and are withheld; every count
the paper reports is reproducible from the metrics here.

## Contents

```
rq1/
├── metrics/                     per-run, per-round counts (the released run-level output)
│   ├── A1_customapp/seed<1..5>/<page>_metrics.csv     SQLi: login, search, product, filter
│   └── A2_customxss/seed<1..5>/<page>_metrics.csv     XSS: search, calc
├── rq1_run_summary.csv          one row per (family, page, seed), consolidated counts
├── rq1_uniqueness.csv           exact-dedup diversity counts, pooled over the 5 seeds
└── README.md
```

Scope: 5 seeds. SQLi has 4 contexts, XSS has 2, so `metrics/` holds
5x4 + 5x2 = 30 files. Each `*_metrics.csv` has one row per generation round with
the funnel counts (`generated`, `backend_valid_n`, `waf_blocked_n`,
`waf_bypassed_n`, token counts, and more).

## Payload-free guarantee

Every value in every file here is numeric. The build step parses each metrics
file and rejects it if any non-header cell is not a number, so no payload text can
be present. The per-candidate records (`*_records.jsonl`), the winners files, and
the per-category corpora, all of which contain payloads, are **not** in this
repository. See `../../data/attack-corpora.md`.

## Fields (`rq1_run_summary.csv`)

| Column | Meaning |
| --- | --- |
| `family`, `page`, `seed` | condition and run |
| `rounds` | generation rounds in the run |
| `requested_per_round` | candidates requested per round (50) |
| `unique_generated` | candidates entering the funnel, after exact within-round dedup |
| `non_executable` | candidates that failed parsing/formatting |
| `backend_valid` | attacks confirmed to exploit the application |
| `crs_blocked` | valid attacks blocked by baseline CRS |
| `crs_bypassed` | valid attacks that bypassed baseline CRS |
| `crs_bypass_pct_of_valid` | per-run bypass rate |
| `bypasser_diversity_pct` | near-duplicate diversity of the bypassers (threshold 0.3) |
| `input_tokens`, `output_tokens` | model token accounting |

## Reproducing the paper's RQ1 numbers

From a clean checkout:

```
python analysis/rq1_aggregate.py            # summary table, dedup stats, per-round trajectory
python analysis/rq1_confidence_intervals.py # 95% Student-t CIs of the bypass rate
```

Both read only the payload-free metrics here. The aggregator reproduces the paper's
headline RQ1 result exactly: baseline CRS bypass of **97.7-99.6%** of valid SQLi
attacks and **74.3-80.8%** of valid XSS attacks (mean over the 5 seeds).

## Exact-string deduplication (`rq1_uniqueness.csv`)

Exact-string duplicate counts are provided, pooled across the 5 seeds of each page,
in `rq1_uniqueness.csv`. This reproduces the paper's RQ1 diversity table.

| Column | Meaning |
| --- | --- |
| `generated` | total candidates produced over the 5 runs |
| `unique_generated` | distinct payload strings among them (exact dedup) |
| `exact_duplicates` | `generated - unique_generated` |
| `valid`, `unique_valid` | valid attacks, and distinct payloads among them |
| `bypasses`, `unique_bypasses` | CRS bypasses, and distinct payloads among them |
| `pct_unique` | `unique_generated / generated` |

These counts are computed from the raw per-candidate records by comparing payload
strings exactly. The records themselves contain payloads and are not in this
repository, so the file is released as a result artifact (the counts), not
regenerated by a script that runs on the repo. The values match the paper exactly.

Two related notes on the per-round metrics:

- The per-round `unique_generated` in `metrics/` is the count after exact
  within-round dedup. The pre-dedup response size is not persisted per round, so a
  per-round duplicate count is not available; the pooled exact-dedup counts above
  are the released form.
- `bypasser_diversity_pct` in `rq1_run_summary.csv` is a separate near-duplicate
  diversity measure of the confirmed bypassers (threshold 0.3), not exact dedup.
